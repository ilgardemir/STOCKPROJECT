# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Squall** — an equity analysis tool with two engines. (1) A single-ticker analyzer: a Python scraper gathers market/fundamental/filing data for one stock, a Node server orchestrates the request and layers an LLM write-up on top, and a vanilla-JS front end renders a dashboard plus a streaming AI analysis and follow-up chat. (2) A natural-language multi-index screener: you describe the kind of company or chart setup you want in plain English, an LLM translates it into a strict measurable "recipe," and a separate Python engine scores a selected S&P 500, Nasdaq-100, Dow 30, or combined universe deterministically. No frameworks, no build step, no npm dependencies.

## Commands

```bash
# Run the whole app locally (serves UI + API on PORT, default 3000)
node server.js                 # → http://0.0.0.0:3000

# Run the scraper standalone — prints the full JSON payload to stdout.
# This is the primary way to debug/inspect data without the AI layer.
python3 scraperFinal.py AAPL   # any ticker; defaults to AAPL if omitted

# Run the screener engine standalone — reads a JSON job on stdin, prints results to stdout.
# echo '{"tickers":["AAPL","MSFT"],"names":{},"spec":{"concepts":[{"id":"momentum","weight":1}]}}' | python3 screener.py
# Env knobs: SCREENER_LIMIT=N (cap universe for a fast test), SCREENER_CACHE_TTL, SCREENER_CACHE_PATH.

# Run the hidden point-in-time analyzer engine. The AI prompt never contains outcomes.
# echo '{"query":"AAPL","as_of":"2023-03-15"}' | python3 backtester.py

# Install Python deps (no lockfile; Node has zero deps so no npm install needed)
pip3 install -r requirements.txt

# Container build (matches Railway deploy)
docker build -t squall .

# Offline unit + contract checks (no API keys or network calls)
npm test
# Individual groups
npm run test:js
npm run test:py
npm run test:contracts
```

There is still no linter or build step. `npm test` runs the zero-dependency Node harness, Python `unittest` coverage, the three-way screener vocabulary drift check, and the SEC provider-pressure audit. Integration testing still means running the scraper on a ticker and/or hitting the running server.

## Environment variables

- `OPENROUTER_API_KEY` — **required** for any AI output; server.js falls back to a placeholder that will fail. All LLM calls go through OpenRouter (`openrouter.ai/api/v1/chat/completions`).
- `SQUALL_AI_MODEL` (analysis/backtest/chat, default **`openai/gpt-5.6-luna`**) and `SQUALL_UTILITY_MODEL` (screener language work only, default `deepseek/deepseek-v4-flash`). Separate knobs on purpose — the utility model does cheap translation and should not be dragged upmarket with the analysis model. **Changing `SQUALL_AI_MODEL` to a frontier model without also setting `SQUALL_AI_FREQ_PENALTY=0` breaks every request.** `require_parameters: true` rides along with a non-zero penalty and filters the provider pool to hosts implementing *every* parameter sent, `temperature` included; measured against the OpenRouter catalogue on 2026-09-08, **no** frontier model advertises `frequency_penalty` (the whole GPT-5.x family, Claude Opus/Sonnet 5, every Gemini 3.x) and several — GPT-5.6 Luna, Claude Sonnet 5 — do not accept `temperature` either. The pool empties and the request fails with "No allowed providers are available" instead of degrading. Everything that *does* implement the penalty is in the cheap flash tier, which is the same class of model the repetition loops come from, so **the damper and a frontier model are mutually exclusive** — pick one. The server already logs a pointer to the reverting knob when it sees that error.
- **The Luna switch was measured on the same 15 `/ilgar` cases, and the reliability result is the whole justification.** Degenerate output went to zero: **2 truncations → 0, 4 corrupted runs → 0, 3 runaway generations → 0**, with average prose collapsing 20,410 → 5,339 characters into a tight 4,968–5,793 band and reasoning 13,552 → 1,191. The sweep ran in **6.6 minutes against 23.2**. **Direction accuracy did not move at all — 6/15 both times** (mean trade −0.30% → −0.18%, median actually worse), and only one of fifteen calls flipped direction, so this bought reliability and speed, *not* predictive skill; do not let the clean numbers imply otherwise. **The cost surprise is that it is 1.61×, not the ~5.6× the per-token prices suggest**: Luna is ~6.7× dearer per output token but emits ~5× fewer of them, because the old model's runaway loops were themselves a large part of the bill — roughly $9/mo → $14/mo at the 150-analyses/day budget ceiling. One consequence to expect: OpenAI models keep reasoning internal, so **1 of 15 runs streamed no reasoning at all** and the "Show thinking" panel can legitimately come back empty.
- `FINNHUB_API_KEY` — recommended; supplies live quotes, company profiles, basic metrics, and dated company-news records. Without it, the analyzer continues with Yahoo/SEC data but does not show company news.
- `FMP_API_KEY` — optional; enables Financial Modeling Prep cross-check data in the scraper.
- `SEC_USER_AGENT` — sent to SEC EDGAR; defaults to a hardcoded string with a contact email (EDGAR requires a real UA).
- `PORT` — injected by Railway at runtime; defaults to 3000.
- `PYTHON_BIN` — python executable name; defaults to `python3`.
- `SQUALL_STATS_KEY` — enables `GET /stats?key=…`. **Unset means the route 404s**, so leaving it unset is a safe default, not a broken one.
- Output-quality knobs — `SQUALL_AI_FREQ_PENALTY` (0–2, **default 0**) and `SQUALL_AI_TEMPERATURE` (0–2, default 0.3). **The penalty defaults to 0 because the default model cannot accept it, not because it was judged useless** — and `temperature` is in the same position: GPT-5.6 Luna implements neither, so both are silently dropped by OpenRouter (harmlessly, since `require_parameters` is off). Restoring the damper means restoring the flash-tier model too. It is worth knowing what the damper did *not* buy: on `deepseek-v4-flash-0731` with the penalty at 0.3, a 15-case `/ilgar` sweep still produced **4 corrupted runs and 2 runaways of 79k and 88k characters** — it was not preventing the failure it was added for, which is a large part of why the swap was worth making. The original reasoning follows, and still applies to any flash-tier model. The penalty exists because **"the analysis cut off" and "the model repeated itself into nonsense" are one failure, not two**: reasoning and answer share `max_tokens`, so a degenerate loop inside the thinking eats the budget the write-up was going to be written with, and the answer then arrives truncated or never starts. `frequency_penalty` scales with how often a token has already appeared, which is the shape of that failure; `presence_penalty` is a flat one-off charge and is deliberately left at 0, so the model can still reuse the vocabulary a financial write-up needs. Keep the value mild — high values push a model off domain terms into paraphrase. **Setting the penalty to 0 also drops `require_parameters`, and that coupling is the escape hatch**: OpenRouter silently drops a sampling parameter the routed host doesn't implement, so `require_parameters: true` is what makes the damper real — but it filters the provider pool *before* `allow_fallbacks` can reroute, so a model with no host implementing the penalty fails with "No allowed providers are available" instead of degrading. `SQUALL_AI_FREQ_PENALTY=0` reverts routing to exactly what it was, from the dashboard, with no deploy. The server logs a pointer to that knob when it sees that error.
- **`effort` is a hint the serving host may ignore; `SQUALL_REASON_MAX_TOKENS` (default 4000) is the one that binds.** `effort: "low"` is nominally ~20% of `max_tokens`, so ~3200 reasoning tokens at `ANALYSIS_MAX` 16000. Measured on `/backtest-stream` it was not binding at all: single replays produced **47,000–62,000 characters of reasoning** (~12,000–15,500 tokens, 75–97% of the whole budget), and since thinking and answer share that budget the write-up came back corrupted, truncated, or empty — INTC 2024-07-15 spent 61,526 characters thinking and emitted nothing. `reasoning.max_tokens` is the absolute form of the same control and gives the answer a guaranteed floor of `ANALYSIS_MAX - REASON_MAX_TOKENS`. All four reasoning call sites go through `reasoningConfig()` so the analyzer, the backtest route and `/chat` cannot drift. `SQUALL_REASON_MAX_TOKENS=0` reverts to sending `effort` alone from the dashboard — the same escape-hatch shape as `SQUALL_AI_FREQ_PENALTY=0`, and for the same reason.
- **A prompt edit on a reasoning route is never free, and the cost lands somewhere you are not looking.** Adding two direction guardrails as prose *tests* ("RSI below 32 together with either volume above 1.5× the 20-day average or a drawdown greater than 45%…") tripled-to-octupled reasoning length on the same model, same effort, same cap — each conditional is a computation the model performs in the thinking budget. The write-ups were *substantively better* (they evaluated the test, cited the new `levels_note`, shortened the horizon around an earnings window, and finally returned a conviction other than 3) and simultaneously unreadable: words run together, doubled punctuation, or no answer at all. **Anything decidable from the numbers belongs in the engine as a decided flag, not in the prompt as a test** — that is what `direction_guardrails` in backtester.py is, and it collapsed three paragraphs to one sentence. A test fails if the analysis instruction block grows past 2,600 characters. After changing any prompt on a reasoning route, read `describeAiStream`'s `reasoning=` figure before assuming the change was free.
- AI speed knobs — `SQUALL_REASON_EFFORT` (`none`/`minimal`/`low`/`medium`/`high`/`xhigh`/`max`, default `low`), `SQUALL_ANALYSIS_MAX` (total output cap, 16000), `SQUALL_CHAT_MAX` (the `/chat` equivalent, 8000 with thinking on, half that without), `SQUALL_AI_PROVIDER_SORT` (`throughput`/`latency`/`price`, default `throughput`). All validate against a fixed set or range and fall back to the default on a typo. **`effort` is a percentage of `max_tokens`, not an absolute budget** (~95/80/50/20/10% for max/high/medium/low/minimal), so raising `SQUALL_ANALYSIS_MAX` silently raises the thinking budget with it — that coupling is why a "medium" setting that looked conservative was never actually binding. **The caps are ceilings, not targets**, and billing follows tokens actually generated, so a generous cap costs nothing on the requests that didn't need it: 6000 was raised to 16000 because at `low` effort it left only ~4800 for the write-up and a full six-section analysis kept hitting it, which surfaces as `truncated: true` rather than as an answer. `/chat` was the worse case — a hardcoded 2048 with thinking off — and is now the same shape of knob. `none` disables reasoning entirely and would empty the UI's "Show thinking" panel. Routing sort is the free lever: OpenRouter load-balances on **price** by default, which is how a fast model ends up on a ~16 tok/s host; `throughput` ranks by generation speed at identical output quality. Measured on the same JPM analysis before and after: **225s → 39s end-to-end**, time-to-first-answer-token 123s → 9s, generation ~16 → ~106 tok/s, with the answer coming out *slightly longer* rather than truncated. Decomposing it, routing accounts for the large majority and the effort drop for maybe a quarter — so if analysis depth ever looks thin, **raise `SQUALL_REASON_EFFORT` back to `medium` before touching routing**. The one cost worth watching: sorting by throughput means no longer picking the cheapest host for a given model, so OpenRouter spend per analysis can rise; `price` reverts and `latency` is the middle ground.
- Abuse limits — every knob in the `LIM` block at the top of server.js reads an env var, so limits retune from the Railway dashboard without a code deploy. The ones worth knowing: `SQUALL_GLOBAL_AI_DAILY` (weighted AI credits/day, default 1500), `SQUALL_GLOBAL_SCRAPE_DAILY` (600), `SQUALL_GLOBAL_SCREEN_DAILY` (200), `SQUALL_IP_HOURLY` (45), `SQUALL_IP_DAILY` (120), `SQUALL_IP_ANALYZE_DAILY` (60), `SQUALL_MAX_PY` (3), `SQUALL_MAX_QUEUE` (10), `SQUALL_SCRAPER_TIMEOUT_MS` (180000), `SQUALL_SCREENER_TIMEOUT_MS` (240000), `SQUALL_STATE_PATH`, `SQUALL_TRUST_PROXY`, `SQUALL_CLIENT_IP_HEADER`. Note the AI budget is the binding ceiling in practice: at `COST.analyze.ai` of 10, 1500 credits is ~150 full analyses/day site-wide, well before the 600 scrape ceiling. **The per-IP trio and the global ceiling do different jobs and should be tuned separately** — the per-IP numbers are the anti-abuse dial and were raised from 20/60/25 so an evaluation sweep against `/ilgar` can run from one address without tripping a gate every twenty runs; that does not raise worst-case spend, because `GLOBAL_AI_DAILY` is unchanged and is what actually bounds the money. If abuse ever shows up in `/stats`, lower the per-IP numbers first.
- `SQUALL_SCRAPER_PATH` / `SQUALL_SCREENER_PATH` / `SQUALL_BACKTESTER_PATH` — override the engine scripts. **Testing only** — they exist so the engines can be stubbed to exercise server behavior on a box without Python. Production leaves them unset. Pair with `PYTHON_BIN=node` and a `.js` stub to exercise the full server path (queue, budgets, cache, SSE) on a box with no Python at all — that is how the analysis cache was verified.
- Upstream-pressure knobs — these protect **provider standing**, not cost, and are the ones to be careful with (see "Protecting provider standing"). `SQUALL_SEC_RATE_PER_PROC` (3.0 req/s per scraper process), `SQUALL_SEC_MAX_FILING_FETCHES` (40 filing documents per analysis), `SQUALL_SEC_TICKERS_CACHE` / `SQUALL_SEC_TICKERS_TTL` (ticker-directory cache, 7 days), `SCREENER_RETRY_BUDGET` (60 extra requests per screen), `SCREENER_THROTTLE_BACKOFF` (5s), `SQUALL_ANALYSIS_CACHE_TTL_MS` (300000) / `SQUALL_ANALYSIS_CACHE_MAX` (60).

## Architecture

The primary flow is **browser → Node server → spawns Python scraper → OpenRouter LLM → streamed back to browser**. The screener adds a parallel flow: **browser → Node server → (LLM interprets query) → spawns Python screener → streamed back**. Four Python/JS files hold essentially all the logic, with `sp500.js` and `market-universes.js` providing index constituents.

### `scraperFinal.py` (~1500 lines) — the single-ticker data engine
Run as a subprocess with one arg (the ticker). Its contract with the server is strict:
- **All JSON goes to stdout** (the payload, or `{"error": ...}`); the server parses stdout as the entire result.
- **Progress goes to stderr** as `STAGE|<n>|7|<label>` lines. The server parses these live to drive the frontend progress bar. There are **7 stages** — this count is duplicated as `STAGE_TOTAL` in server.js, so changing the stage count means editing both files.

`generate_analysis_payload(query)` is the orchestrator (starts ~line 967; takes a ticker **or** company name, which it resolves). Data sources: SEC EDGAR (CIK lookup, company facts, recent filings, 10-K MD&A text, 8-K/Form 4/13D signal parsing); Finnhub (live quote, profile, metrics, and company-news records); optional FMP cross-checks; and yahooquery (5y price history, financial statements, options, intraday, plus SPY for beta/relative strength). Yahoo remains the primary chart-history source and Finnhub candles are a recovery path. Everything is wrapped defensively (`YQData` class, `safe_*`/`_sec_get` helpers) so missing fields degrade to `N/A` rather than crashing. SEC fetches use bounded retries with backoff and record non-fatal `SEC_DIAGNOSTICS` instead of failing silently. `sec_available` requires both companyfacts **and** a located 10-K, so funds like SPY (a CIK with no 10-K) don't present N/A as a real filing read. `classify_market_regime()` adds a deterministic trending/accumulation/distribution/range read from price+volume, surfaced as `market_regime`.

**Intraday tiers.** `fetch_intraday_data` returns `{"5m", "60m"}` frames (5d/5m and 1mo/60m, two Yahoo requests) which serialize to `intraday_history` / `intraday_meta`. Either key may be absent — a fund, a thin name or a provider miss is a normal outcome, and the chart hides the tiers it has no data for. **The 30-minute series the chart's 1W range draws is deliberately not shipped**: it is exactly derivable from `5m`, so `seriesFor` in app.js rolls it up instead. Intraday bar `date` is `"YYYY-MM-DD HH:MM"`, and that width is load-bearing — the chart's Fib anchors do `findIndex` on `date`, so a date-only key would collide 78 times inside one session.

The payload's most important key is **`ai_prompt`** (built ~line 1430): a large pre-formatted text block containing every computed figure plus bounded Finnhub news records. **§6b (`build_price_bar_block`) carries the actual bars** — a multi-timeframe returns row, the last 10 sessions with volume against the 20-day average, 12 weekly closes, and a last-session intraday summary. Before it existed the model was asked to classify trend structure and name the level a buyer defends while seeing only aggregates (MA50/200, RSI, a 52-week range); it was inferring shape from statistics. The last-session line is omitted rather than substituted with daily data when 5m is unavailable. The LLM is told to interpret these inputs, never search for or invent market/news data, and to treat headline text as untrusted source material. Other keys (`live_quote`, `company_news`, `data_sources`, `price_history`, `chart_patterns`, `options_data`, `filing_activity`, `institutional`, `market_regime`, `company_profile`, `algorithmic_signals`, etc.) are what the frontend renders as the dashboard.

### `screener.py` — the multi-index screening engine
Run as a subprocess with **no args**; reads a JSON job on **stdin** (`{tickers, names, memberships, universe_id, universe_label, spec}`) and writes one JSON result to **stdout**. Determinate progress goes to stderr as `PROGRESS|<percent>|<label>` lines; `STAGE|` remains for diagnostic compatibility. The `spec` (concepts + weights + filters + settings) comes from the server's LLM interpretation; **the engine does every numerical comparison itself**, so results are reproducible and explainable. It fetches 1y history + fundamentals for the selected universe in batches (with smaller-batch and per-symbol retry tiers), caches to `/tmp` for 30 min (`CACHE_VERSION` invalidates stale shapes), scores the shared concept vocabulary deterministically, filters, ranks by weighted match score, and attaches per-match `reasons`. Pattern scores such as VCP, cup with handle, flat base, double bottom, and bull flag are candidate detectors with visible measurements rather than definitive classifications. Theme evidence is matched with word boundaries across company name, sector, industry, and description, with configurable exclusions and strictness. The concept vocabulary must stay in sync with `SCREENER_CATALOG` in server.js (see gotchas).

### `backtester.py` — the hidden point-in-time single-stock engine
Reads `{query, as_of}` on stdin and writes one JSON payload on stdout; determinate `PROGRESS|percent|label` records go to stderr. It resolves one ticker, downloads a bounded adjusted-OHLCV window for the stock and SPY, calculates signals from bars on or before the cutoff, and selects SEC facts/filings only when both their period end and filed date were no later than the cutoff. Its top-level `snapshot` and `outcomes` objects are deliberately separate. `ai_prompt` is serialized from `snapshot` alone. Historical news, options flow, estimates, and index membership are explicitly marked unavailable rather than substituted with current data.

**`event_risk` estimates when the issuer's next results land, and it breaks no seal.** Every input is a `(period_end, filed)` pair from a filing already dated on or before the cutoff; it reconstructs the issuer's reporting rhythm, which was as knowable on the cutoff date as any price on the chart. It exists because an 18-run audit found the model trading blind through scheduled events: one of eighteen analyses mentioned an upcoming report, while the five cases with results due inside three weeks averaged **-15.1% over the following month** against +1.4% for the other thirteen. Two things about it are load-bearing. **The anchor is the period that has ENDED but has NOT been reported**, not the last one filed — INTC at 2024-07-15 had last filed for the quarter ended 2024-03-30 while the quarter ending 2024-06-29 was already over and outstanding, and anchoring on the filed one projects a full quarter late and misses the event entirely. And **`_snap_period_end` pulls the day-count projection back onto the issuer's own calendar**: adding a 92-day cadence to 2024-12-31 lands on 2025-04-02, two days past the quarter it means to name, and the error compounds every step. The snap fires only for month-end filers, because a 4-4-5 filer (INTC ending 2024-06-29, NVDA 2022-10-30) advances by exactly 52 weeks and the raw cadence is already right to the day.

**`direction_guardrails` decides the two direction rules here rather than arguing them in the prompt.** Both close off the SHORT side only, which is what the audit supports — the catastrophic misses lived in the short book (NVDA +166% and AMD +145% *against* a short). No mirror-image long rule is asserted because none was measured. The rules: price above all three moving averages while the averages are still stacked bearishly (the stack lags price, so that shape is a reversal in progress), and capitulation (RSI < 32 with either volume > 1.5× the 20-day average or a drawdown deeper than 45% from the 52-week high). **META 2022-02-15 has a test specifically asserting it is NOT blocked** — RSI 27 but volume 0.83× and 42.5% off the high, so neither limb fires — because orderly-downtrend shorts were 3-for-3 in the audit and a sloppier guardrail would have destroyed the one thing the model does well.

**The prompt is a projection, not the snapshot.** `PROMPT_BLOCKS` names what the model sees, and two transforms run on the way out. `facts_for_prompt` cuts `sec_facts` to `PROMPT_FACT_PERIODS` (5) and strips `fiscal_year`/`fiscal_period`/`period_start` from every row but the newest — measured at 29,000-30,300 characters of a ~37,600 character prompt, `sec_facts` was **77-80% of everything the model read** to produce two lines of YoY growth it then set aside, while `market_regime` got 547 characters and decided the trade in 18 of 18 runs. `scraper.regime_for_prompt` drops `confidence` (see the gotchas). Together they cut the prompt ~48% on real payloads with nothing the write-ups were using.

### `server.js` (~880 lines) — orchestrator + LLM gateway
A raw `http` server (no Express). Endpoints:
- `GET /analyze-stream?ticker=` — **the main path.** Server-Sent Events. Spawns the scraper, relays `progress` events from stderr, sends the parsed payload as a `result` event the moment the scraper finishes, then opens a streaming OpenRouter call and forwards `ai_thinking` / `ai_delta` tokens, ending with `ai_done` or `ai_error`. The AI call retries up to 3× **but only before the first token is emitted** — retrying mid-stream would duplicate text in the browser. Accepts an optional `profile=` (MySquall) param.
- `GET /screen-stream?q=&universe=` — SSE screener. `universe` accepts `combined`, `sp500`, `nasdaq100`, or `dow30`. First the LLM turns `q` into a measurable spec (`interpretScreenerQuery`; falls back to a regex-based `fallbackScreenerSpec` with no API key), emits `screen_interpretation`, then spawns `screener.py` and emits determinate `screen_progress` percentages → `screen_result` / `screen_error`. Passing `existing=` + `result_count=` switches it into **refinement** mode (`refineScreenerSpec`): a follow-up message revises the prior recipe and emits an extra `screen_reply`. All numeric/string inputs from the model are re-sanitized server-side against fixed enums and ranges before reaching Python. `applyProfileCalibration` then reapplies MySquall holding-period, risk, style, and priority settings as visible secondary tilts while preserving explicit request concepts.
- `GET /backtest-stream?ticker=&as_of=YYYY-MM-DD` — hidden single-stock historical analyzer used by `/ilgar`. It emits the frozen snapshot first, sends only `ai_prompt` to OpenRouter, and does not emit `backtest_outcomes` until the AI stream has ended or failed. Every completed replay is forced to a labeled long/short position: the extracted blind AI call supplies direction when usable, otherwise a deterministic pre-cutoff signal fallback does. **MySquall sets the risk bounds, but as ceilings rather than fixed values** — `ensureBacktestPosition` clamps a stop to the profile cap and floors the target at `stop x reward_ratio` as before, but the horizon is now only shortened, never lengthened (a shorter hold cannot breach a preference expressed as "how long am I willing to be exposed"; overwriting unconditionally made all 18 audited runs execute at 3m including the four that asked for 1m, and scored WMT 2025-01-15 a miss on a -0.1% three-month return after it asked for the month over which the stock rose 13.7%). **Conviction now scales `position_pct`** via `[0.4, 0.7, 1.0, 1.3, 1.6]`, re-clamped to the same 0.05-0.75 band, and is centred on 1.0 at conviction 3 so an unchanged profile sizes exactly as it did. It was previously rendered and discarded, which left the model no way to bet more on a setup it believed in — and, predictably, the number carried no information either: 17 of 18 audited extractions returned exactly 3 and none returned 1, 4 or 5. Both ends of the scale are now anchored explicitly in the analysis prompt and again in the extraction prompt, because an unanchored 1-5 scale collapses to its midpoint. Options profiles are explicitly tested through the underlying stock proxy because no historical option chain is available. The route uses the normal analysis abuse budget, Python queue, and timeout. `/ilgar` is unlinked and `noindex`, but it is obscurity rather than authentication.
- `POST /analyze` — non-streaming equivalent (`exec` instead of `spawn`); returns one JSON blob. Kept as a fallback.
- `POST /chat` — SSE follow-up chat. Takes prior `messages`, the stock `context`, the initial `analysis`, a `think` flag, and optional `profile`. Note the deliberate comment: it listens for `close` on **`res`, not `req`** — listening on `req` aborts instantly in Node 16+ and yields blank replies.
- `GET /health` — Railway healthcheck. Deliberately dumb and deliberately unchanged: it is public, so it must never leak remaining budget.
- `GET /stats?key=` — owner-only spend snapshot (see Abuse limits). Fails closed: 404s unless `SQUALL_STATS_KEY` is set and matches.
- Any other GET — static file serving from the repo root, via `serveStatic`. It does four things beyond reading a file: rewrites extensionless paths to `.html` so pages get clean URLs (`/screener` → `screener.html`), expands `<!--#include -->` directives from `partials/`, sets `Cache-Control` + `ETag` so assets revalidate into 304s, and answers a miss with the `404.html` page. **Strip the query string before testing for the root** — checking `req.url === "/"` first misses `/?t=AAPL`, whose path is still the root, and the extensionless rewrite then turns the empty remainder into `.html` and 404s the analyzer's own deep link.
- **The 404 page is sent by `sendNotFound`, and its two conditions matter.** It goes out only when the client sent `Accept: text/html` *and* the miss is page-shaped — post-rewrite that is exactly "did the path end up `.html`", since extensionless URLs have already become one and real assets never do. Without both, a missing PNG answers with 12 KB of markup under an image content type and an `EventSource` gets HTML where it expects `text/event-stream`; everything else still gets `text/plain`. An unreadable `404.html` degrades to that plain text rather than throwing — the error path is the one path that cannot have an error path. Status is always a real 404, `/404` and `/404.html` included (serving *those* a 200 would make the page whose job is to report failure the one page reporting success), and the wrong-key branch of `/stats` routes through the same helper so "no such key" and "no such route" stay byte-identical.

#### Abuse limits

The site is public and anonymous, and every cost path spends real OpenRouter/Finnhub credit plus a Python subprocess. The `// ─── ABUSE LIMITS ───` section (between `serveStatic` and `http.createServer`) exists to make worst-case daily spend a number you choose. It is deliberately invisible to a normal visitor — no captcha, no login.

- **Four gates, called explicitly.** `admit(req, kind)` runs at the top of `/screen-stream`, `/analyze-stream`, `POST /analyze`, and `POST /chat` — **not** at the top of the request handler. Static files fall through the catch-all `GET`, so a blanket gate would throttle page loads (one page view is 5+ requests). `/health` and `serveStatic` are exempt *by construction* because they never reach a gate; there is no allowlist to keep in sync.
- **Two budgets, spent at different times.** `admit()` charges per-client burst/hourly/daily counters plus the global scrape/screen ceilings *before any work*, because a client that opens an SSE stream and aborts has already cost a subprocess. `spendAi()` charges the global AI budget *immediately before the first OpenRouter call* — on `/analyze-stream` that is deliberately **after** `send("result")`, which is the whole trick behind data-only degradation. Charge once per logical request, never per attempt: the analyzer's retry loop is 3 HTTP calls for one analysis. **There is no refund path, on purpose** — spending after the point of no return means there is nothing to refund, and adding one only introduces double-counting.
- **Degradation, not failure.** Out of AI budget, the analyzer still scrapes and still renders every number and emits `ai_error` with `limited:true`; the screener falls back to its deterministic rule-based recipe builder and still returns scored results; chat refuses honestly with a 503 (it has no data-only equivalent). The scrape ceiling is separate and tighter than the AI one, because it protects Finnhub quota and — harder to undo — the deployment IP's standing with Yahoo/SEC.
- **Client identity is IP-only**, because `EventSource` cannot send custom headers. Forwarding headers are consulted **only when the TCP peer is itself private**, i.e. when something actually terminated the connection in front of us; directly exposed, every `x-forwarded-for` is attacker-controlled noise and is ignored. Behind a proxy we take the **rightmost** public entry (what the edge appended from the real peer), never the leftmost (what the client typed). IPv6 keys bucket to **/64** — per-address counting would hand one attacker 2^64 free buckets.
- **State is in-memory with a temp-dir mirror** (`os.tmpdir()`, not a hardcoded `/tmp` — the latter breaks local verification on Windows). It survives a crash-restart inside a deploy; surviving a redeploy is explicitly not a goal. Only daily counts are restored, never burst tokens or hourly counts — restoring those would punish users for our crash. Written temp+rename so a kill mid-write can't leave truncated JSON.
- **Subprocess concurrency is a bounded queue**, not a reject: `MAX_PY` (3) run, `MAX_QUEUE` (10) wait, past that it's a 503. Queued SSE clients get a position tick every 5s, which is **not cosmetic** — app.js keeps the analyze button disabled until a terminal event arrives, so a silent wait reads as a hang.

#### Protecting provider standing

Budget is a number you choose and can raise. **Provider standing is not** — Yahoo (via yahooquery, unofficial and against its ToS), SEC EDGAR and Finnhub can all block the deployment IP at any time, with no appeal, and a Yahoo block degrades the analyzer *and* kills the screener outright, since the screener has no fallback source. Everything in this subsection exists to keep the request **rate** low, which is a different problem from the daily cost ceilings above and is bounded by different code.

- **Never retry harder into a failure.** The screener's batch fan-out (`get_history`) once turned a failed 50-symbol batch into up to 105 requests — while the most common reason Yahoo drops a batch is that it is *already* throttling us. Fan-out is now gated on the failure signature, stops for the rest of the run once `_throttled` is set, and draws from `SCREENER_RETRY_BUDGET`. Any new retry path needs the same three gates; retrying into a 429 is how a throttle becomes a block.
- **`MAX_PY` is the rate knob, not a throughput knob.** The daily scrape/screen ceilings are for cost comfort; concurrency is what actually sets requests-per-second. Raising `SQUALL_MAX_PY` scales SEC pressure linearly, so raise `SQUALL_SEC_RATE_PER_PROC` *down* in the same change — the scraper self-limits per process precisely because subprocesses have no shared state to coordinate through.
- **Caches are load-shedding, not just speed.** The analysis cache (server.js) and the screener's merged, per-entry-timestamped cache both exist to keep repeat traffic off the providers. The screener cache tracks which tickers were *attempted*, not which produced rows — judging by rows meant one symbol with under 65 days of history failed the coverage check forever and forced a full cold pull of ~600 symbols every single run.
- **Watch `providers` in `/stats`.** `rate_limited` counts per source are the earliest available warning of a block. Engine warning lines are logged as they arrive even when the run succeeds; they used to be discarded unless the run failed, which hid exactly the case worth seeing.

**The replica trap.** The limiter, the analysis cache, and both engine caches are per-process/per-container. Scaling Railway to more than one replica therefore gives each replica its own full daily budget and its own cold caches — multiplying spend *and* provider load — with nothing in the running system to signal it. **This is the most expensive mistake available in this codebase, and it looks exactly like the obvious fix for load.** Shared state (Redis or equivalent) is a prerequisite for a second replica, not an optimization to follow one.

LLM config lives in the CONFIG block at the top. `buildAiMessages()` assembles the analyst prompt; `formatProfile()`/`sanitizeProfile()` fold the MySquall profile in as *personalization only* (explicitly told never to override facts or safety rules, and free-text is labeled untrusted — prompt-injection hygiene). `SCREENER_CATALOG` is the authoritative concept dictionary (id → label + plain-English definition) shared with the interpreter model and the frontend.

### `index.html` + `screener.html` + `styles.css` + `app.js` (~2400 lines) — the front end
No framework. **Two pages, one script, one stylesheet.** `/` is the analyzer (hero, dashboard, chart, chat) and `/screener` is the screener; both load the same `app.js` and `styles.css`. Key structure:

- **`404.html` is the exception: it shares the stylesheet and nothing else.** No `app.js`, no `partials/` chrome. app.js is 148 KB of analyzer/screener machinery parsed to render a dead end, and every element lookup in it is one more way for the error page to itself error — the one page that must not break is the wrong place to load the file most able to. The cost is that the two things it would have provided are restated inline: **the theme has to be applied before first paint** (or someone running Paper gets a flash of Midnight), so the id→mode map mirrors `THEMES` in app.js and adding a palette means editing both. Its own markup borrows classes freely but **not `.search-ico`** — that one is absolutely positioned against the header's `.ticker-wrap` with two media queries nudging its `left`, so reused here the glyph lands in the page margin; `.nf-ico` exists for that. The search field hands off via `/?t=`, the same deep link the screener uses, so the analyzer stays the only thing that runs an analysis.

- **Shared chrome is server-side included, not duplicated.** `partials/chrome-top.html` (header, `#tickerBar`, the Saved popover, MySquall modal) and `partials/chrome-tabs.html` (storage notice) are stitched in by `expandIncludes()` in server.js wherever a page contains `<!--#include name-->`. Two partials rather than one because `<body>` is a flex column, so **DOM order is visual order**. Editing shared chrome means editing `partials/`, never a page.
- **Vertical space is the binding constraint, and the layout is budgeted against it.** The target display is **1280×720** — a maximized viewport of ~585px. The analyzer once spent 195px of that (header 58 + summary strip 100 + saved-tab strip 37) on chrome before a single number, then split the remainder in two: **352px of window for 1,990px of cards, 228px for 1,602px of prose**, and `#chatDock`'s 280px CSS default made a *first* visit a 72px reading slot. Everything below exists to hold that budget, and the rule is simple: **a new feature may not introduce a new fixed horizontal band.** Width is affordable here; height is not. Current measurements — header 52, data region 533, AI region 480, chart canvas 463.
- **`#viewRail` is one vertical rail driving both layout modes**, and it replaced two mechanisms that were the same idea at different breakpoints (the horizontal `#dataSections` tablist and `#mobileTabs`' Data/AI switcher). `VIEWS` is the destination list; `pane` says which pane a destination lives in and `focusOnly` keeps the AI ones out of the rail in split mode, where that pane is already on screen. Vertical is not a style choice — a horizontal tab row costs 34–40px of the scarce axis and a rail costs none of it. `--rail-w` is 130px because "Fundamentals" is one unbreakable 94px word; a narrower rail wraps it.
- **Focus mode is `matchMedia("(max-width: 1100px), (max-height: 820px)")`.** Either axis. Height is the half that matters and the half the old width-only 960px breakpoint missed — 1280×720 passed it as "desktop" and got the split that made the analysis unreadable. `syncFocusModeClass` sets `body.focus-mode` so CSS and JS read one condition; `syncPaneVisibility` owns `[data-hidden]` and **must clear it when leaving focus mode**, or a pane silently stays hidden on a wide screen.
- **The chart is a destination, not a card.** As a card it was a fixed 360px canvas plus 93px of wrapped controls inside a 312px window — the controls and the candles could not be on screen together at any window size. It now takes its region's height (`#chartBox { flex: 1 }`), and its eight overlay toggles live behind an `Overlays ▾` popover, so the control strip is 28px. `drawChart` needed no change (it already measures `clientWidth/clientHeight` and bails on zero) but a fluid canvas needs `observeChartBox()` to tell it when the box resizes. Two traps: **`overflow-x` on `#chartControls` would clip `#overlayMenu`** (a scroll container on one axis forces the other to `auto`), so the sideways scroll lives on `#rangeSel`; and **`expandChart` must not clone `.overlay-wrap`** — that would put a second `#overlayBtn`/`#overlayMenu` in the document, so it clones the toggles out of the menu instead.
- **`PAGE` / `IS_SCREENER_PAGE` / `on()` are the multi-page contract in app.js.** `<body data-page="...">` names the page; `PAGE` reads it. **A bare top-level `document.getElementById(x).addEventListener(...)` is the way to break the other page** — one null throws, the script dies at that line, and every listener below it silently never gets wired. Use `on(id, ev, fn)`, which no-ops when the element is absent. This is not theoretical: nine such sites existed before the split and each one would have taken down `/screener` entirely.
- **Deep links are the point of the split.** `/?t=TICKER` opens or runs an analysis, `/screener?id=<screenId>` opens a saved screen. Before this there was one URL and nothing was linkable, shareable or indexable. `gotoAnalyzer()`/`gotoScreener()` handle the hand-off; `goHome`, `openScreener`, `openSavedScreener`, `switchTicker` and `runAnalysis` each check `IS_SCREENER_PAGE` and either act in place or navigate. Saved tabs and MySquall survive the trip because they were always localStorage, never memory.
- **Styling lives in `styles.css`, not in a `<style>` block.** It was inlined, which meant re-sending 87 KB on every page load and no way to cache it — tolerable for one page, actively wrong for two. `serveStatic` sets `Cache-Control` per extension plus an ETag, so repeat visits answer with a bodiless 304. Pages are hashed over the **assembled** body because a size+mtime tag on the page file alone goes stale the moment a shared partial changes; everything else uses the cheap size+mtime stamp.

Key structure in app.js:
- `sessions` object keyed by ticker (`{ data, context, history, range }`) — the app holds multiple analyzed tickers at once; `active` tracks the current one. Analyses persist as browser-like **saved tabs** (localStorage).
- **What gets persisted is deliberately not what's in memory.** `persistableSession()` writes a trimmed projection: OHLC rounded to 6dp (the scraper's `safe_float` does no rounding, so a close arrives as `234.55999755859375` — 18 bytes where 6 will do, four times across 1260 bars, and now across the intraday series too), `price_history_1y` dropped (a pure alias; both readers are `d.price_history || d.price_history_1y`), and `context` dropped (assigned `data.ai_prompt` at creation, never reassigned, and `hydrateSavedSessions` recovers it). The derived `30m` series is never stored for the same reason `price_history_1y` isn't. Measured on a realistic session: **256 KB → 169 KB, so ~20 → ~30 saved tabs inside a 5MB origin budget.** Anything added to the payload that is derivable or duplicated belongs in that trim. The in-memory session is never mutated by it — `renderAll` must keep working on untrimmed data.
- **A full localStorage evicts; it must never fail silently.** `persistSessions()` used to `return false` on `QuotaExceededError` and not one of its callers looked, so past ~20 saved tabs the pill appeared, the write failed, and the analysis was gone on the next visit with no signal. It now drops least-recently-updated sessions — **never `active`** — until the write fits, deletes them from memory too so the tabs and the store can't disagree, and reports it via `showStorageNotice()`. Refusing the write instead is not the safer option: the session dies at reload anyway, just later and more quietly.
- **UI-churn writes are debounced, state transitions are not.** `scheduleSessionSave()` (400ms) covers range clicks and fib handles; `persistSessions()` stays immediate for the seven paths that must survive a crash (new result, `ai_done`/`ai_error`, stream finalize, retry, delete, chat completion). `persistSessions()` clears any pending timer, and both `pagehide` and `visibilitychange`→hidden flush — a debounced write that never lands is worse than no debounce, and mobile app-switch fires only the latter.
- `screeners` object keyed by screen id — saved screens (recipe + results + refinement chat `history`) also persist to localStorage and appear as tabs. They share the same origin budget, so `persistScreeners()` surfaces a full store through the same notice — but never evicts, since a screen is cheap to re-run and trading one for another isn't a call to make for the user.
- Analysis is driven by `new EventSource("/analyze-stream?...")` with handlers matching the server's SSE event names (`progress`, `result`, `ai_start`, `ai_thinking`, `ai_delta`, `ai_done`, `ai_error`). The screener uses a second EventSource with `screen_*` events.
- Custom canvas charting (candlesticks, MA/BB/Fib/S-R overlays, volume) driven by `chartOpts`; there is no charting library.
- **Chart ranges are timeframe descriptors, not bar counts.** `RANGES` used to be `[label, dailyBars]`, which is why `1W` drew five candles. Each entry now names a `tf` (`5m`/`30m`/`60m`/`1d`) and `seriesFor(d, tf)` is the single place that knows which array backs it — `30m` is rolled up from `5m` by `aggregateBars`, memoized per payload because `drawChart` runs on every hover, drag and repaint. **Aggregation anchors to the newest bar**: anchoring at the front lets a partial leading group shift every bucket as data arrives, so the most recent candle — the one being read — would keep changing. MAs and bands are computed on the *resolved* series, so `MA 20` on a 5-minute chart is twenty five-minute periods. `sess.range` is an **id string**; `normalizeRange` migrates the numeric counts every existing saved tab still holds, and without it `RANGES.find(r => r.id === 252)` is `undefined` and `drawChart` throws on every restored tab. `buildRangeSel` only offers a tier whose series resolved.
- **Overlay levels must not set the y-axis.** S/R and Fib come from the *daily* series and are the same prices on every timeframe, but the window is not: one session of 5-minute bars spans a couple of dollars, so a level 8% away takes the whole scale and the candles collapse into a sliver. The bars set the scale; a level only participates (and only draws) if it lands within a band around them.
- **A range tier is the *default* window; the viewport zooms inside it.** `visibleWindow(len, defaultBars, chartZoom)` is the single resolver and it clamps everything, so no caller reasons about a series shorter than the window it asked for. State is two numbers — `count` on screen and `offset` trimmed off the newest end — and both are counted **in bars from the right edge**, which is the whole reason one viewport can drive two tickers of different history lengths in the compare split without either pane drifting. `zoomWindow` anchors on the pointer (or the pinch midpoint) so the bar you are looking at holds still; anchoring at the edge walks every zoom toward the newest bar. The viewport belongs to the tier: `chartZoom.key` is a range id and `drawChart` resets when it changes, because choosing a range is choosing a window, not zooming the one you had. It is **not persisted** — a view preference of the moment, unlike the compare selection.
- **Gestures: Ctrl/⌘+wheel and trackpad pinch zoom, two-finger pinch zooms, one-finger/mouse drag pans.** A **bare wheel is deliberately not handled** — the chart lives inside a scrolling pane and swallowing the page scroll whenever the pointer crosses a canvas is what makes an embedded chart hostile. `touch-action: pan-y` on the canvas is what makes the rest work: one finger still scrolls the page vertically, while horizontal drags and pinches come to us. A drag only becomes a pan after 3px of travel, so a click is still a click and hover survives a resting mouse. Pinch and pan are absolute against the window captured at gesture start (`st.pinch.base` / `st.drag.base`), never compounded frame to frame, or the rounding walks.
- **The chart is two panes, and `drawChart` is an orchestrator over `paintChartPane`.** `chartSlots()` resolves the primary + compare canvas/tooltip/pane for whichever frame is live (inline `#chartPane`/`#chartPaneB`, modal `#chartModalPane`/`#chartModalPaneB`), and `chartPaneState` holds hover, the reveal sweep and the in-flight gesture **per pane** — a shared hover index draws a crosshair on the chart you are not touching. Three things to know: the compare selection is a localStorage *view preference* resolved at read time by `effectiveCompare()` (a deleted or now-active ticker degrades to "not comparing", never to a blank pane); opening the tab you are comparing against **swaps** the panes rather than dropping half of what you were reading; and a compare ticker need not have the primary's tier at all, so availability is resolved per pane and the pane tag names the interval it actually drew. Fib editing stays on the primary pane only. `chartPaneState` and `chartZoom` are declared **at the top with `RANGES`** for the documented reason: the load-time `applyTheme()` repaints, and a `const` below that call site is a TDZ that throws for every visitor holding a saved tab.
- **The compare control carries no id, on purpose.** `expandChart` clones the control row into the modal bar, so anything with an id there becomes a dead duplicate (that is why `.overlay-wrap` is skipped by the clone). `[data-compare-btn]` / `[data-compare-menu]` / `[data-compare]` are driven by delegation and written by one function, `syncChartChrome()`, which updates *every* copy — call it after a render, after the session list changes, and after any zoom or compare change. In the modal the popover must open **upward**: that bar is at the bottom and `#chartModalInner` clips its overflow.
- **What collapses on a narrow chart row is decided by the pane, not the viewport.** `#chartControls` is `nowrap` and `#rangeSel` is the elastic member, so a tight row does not overflow — the range buttons just quietly scroll out of reach. `syncMetricDensity()` (which already measures `#dataPane`, and is the only thing that can see the split drag narrowing a pane while the viewport stands still) toggles `.tight-controls` under 760px, which drops the interval chip and shortens "Compare" to "vs". Measured: all six tiers survive down to a ~640px pane with that, ~700px without.
- **The data pane is five destinations, not one scroll** — `renderAll` accumulates cards into `bucket` (Chart / Overview / Technicals / Fundamentals / Filings) and `renderViewRail` fills `#viewRail` and returns the panels. It is a regrouping: every card and metric still renders and each keeps its own open/collapsed default. Three rules: wire the rail **by delegation from inside `renderAll`** (`#viewRail` is filled by `renderAll`, so a top-level `getElementById(...).addEventListener` throws at load and kills `/screener` and `/ilgar` too); **repaint the chart when its destination is entered** — a hidden panel is `display:none`, so its canvas measures 0×0 and `drawChart` bails; and **`.data-section.show` keeps a 960px measure** — a metric row is a label and a value on a shared axis, and at the ~1150px a focus-mode pane offers, the eye stops connecting them. The chart panel is the exception (`max-width: none`). The active destination is a localStorage *view preference*, never session state.
- **The chat dock is collapsed to its input row until used.** `syncChatDock(focused)` opens it on the first message or on field focus. `focused` is passed explicitly rather than read from `document.activeElement`, because in a background tab that reports `<body>` even inside a `focus` handler — inferring it makes the dock refuse to open in exactly the case that is hardest to notice. A stored `--chat-h` is **clamped against the live pane**, not trusted: the value found in the wild was the old 120px min-height, dragged there by hand to claw reading space back.
- **`renderAnalysisBody` promotes the verdict** and collapses the remaining `##` sections (Valuation and Price Action open). Wired into `renderAll` and `finalizeAiRender` but deliberately **not** `flushStream` — sectioning a partial stream would collapse text as it arrives. **Below two parsed headers it returns `renderMarkdown(text)` verbatim**; the model goes off-format and an analysis lost behind a parser is far worse than one rendered flat. The prompt is untouched, so the parser and the headers stay in sync by construction. Hold is neutral ink, not `--warn` — green and red are direction, and `--warn` is a distinct role.
- **MySquall** profile (risk/horizon/experience/depth + priorities + free text) is edited in a modal, stored only in localStorage, and sent as `profile=` on analyze/screen/chat requests.
- **Two search fields, one instrument.** `#ticker` (header) and `#heroTicker` (landing hero) share the `.ticker-wrap`/`.hero-search` CSS rules and one `attachTypeahead(input, box, submit)` factory — a custom in-DOM typeahead over the combined names from `sp500.js` and `market-universes.js`, not the native `<datalist>`. Only one is ever visible: a `MutationObserver` on `#hero`'s inline `display` toggles `body.hero-up`, which hides `#searchForm`. The hero field mirrors into `#ticker` before calling `runAnalysis()`, so `#ticker` stays the single source of truth for the analysis path; use `setAnalyzeBusy()` rather than touching either button's `disabled` directly. The hero housing deliberately overrides its border to `color-mix(… var(--ink-dim) 75% …)`: a plain `--rule` hairline measures ~1.1:1 against the page and the field reads as empty space on an open hero — the landing page's whole job is that the search is findable.
- **Six themes**, picked from a menu behind the palette button and persisted in localStorage. The `THEMES` table in app.js (`{id, label, note, mode, bg, accent}`) drives the menu: `dark` (Midnight), `light` (Daylight), `noir`, `paper`, `lagoon`, `matrix` (Terminal). `applyTheme()` sets `data-theme` **and** `data-mode` on `<html>`; canvas code keys off `data-mode` (light/dark), never `data-theme`, and repaints via the `squall:theme` CustomEvent. **A theme owns the neutral ramp and the accent, and nothing else** — `--up`/`--down`/`--warn` (+ softs) are declared once per `[data-mode]` family, after the theme blocks and at equal specificity, so a palette cannot restate what green means. Themes used to redeclare them, which is why Noir read as "greyscaling the whole app". One shared light set has to clear AA against the worst light surface, Daylight's `#eef2f5`, not Paper's white.
- **The theme crossfade is a view transition**, not a transition on `*`. `applyTheme()` runs the swap inside `document.startViewTransition` — two snapshots cross-faded on the GPU, one animating layer regardless of page size — and holds `.theme-swap` (`transition: none !important`) on `<html>` for the duration so nothing double-animates under the snapshot. The old `.theme-anim` rule put a six-property color transition on every element and both pseudo-elements: measured on a 1,864-element page, **3,333 concurrent CSS transitions vs 0**, and the synchronous recalc climbed 103 → 347ms across six consecutive switches while the new path fell to ~26ms. Two consequences worth knowing: the token swap is now **asynchronous** when animating (the callback runs a frame later — never read `dataset.theme` straight after an animated `applyTheme`), and anything that must be inside the fade has to happen inside `commitTheme`, not in a rAF after it — `drawChart()` is there because canvases don't inherit CSS colors. Every promise on the transition object needs a `catch`: a skipped transition (hidden tab, or a second switch mid-fade) rejects `ready`/`updateCallbackDone`, and that is a normal outcome that would otherwise log as an uncaught error.

### The design system

The UI follows a written design direction — **"precision instrument"**: terminal lineage, dense, information-first, minimal chrome, decoration is suspect. The spec is `docs/superpowers/specs/2026-08-04-ui-precision-instrument-design.md` and it is worth reading before any visual change, because most of the rules below exist to serve it and are easy to undo by accident.

**All styling goes through tokens in the `:root` block of `index.html`.** Do not introduce literal colors, font families, or font sizes in a rule.

- **Two type registers, no display face.** `--mono` (IBM Plex Mono) is the instrument: data, labels, chrome, wordmark, card headers. `--doc` (Newsreader, a serif) is the document: AI prose, MD&A excerpts, learn-notes, recipe definitions, chat. The dividing line is *measurement vs. explanation*, not pane position. Size scale: `--t-micro` 10px → `--t-data` 12 → `--t-body` 13 → `--t-lead` 15 → `--t-doc` 16 → `--t-doc-h` 20 → `--t-title` 22. **10px is a hard floor — nothing renders smaller.**
- **Color roles, not color names.** Thirteen roles: `--chrome-0/1/2` (surfaces), `--rule` (hairlines), `--ink`/`--ink-dim`/`--ink-bright` (text) and `--accent` are declared per theme; `--up`/`--down`/`--warn` plus their `-soft` tints (direction only) are declared per `[data-mode]` and are the same in every palette of that family. Legacy names (`--bg`, `--surface`, `--text`, `--green`, `--violet`, …) are **deleted** — do not reintroduce them.
- **Exactly one accent.** `--violet` was removed precisely because it had become an unofficial second accent. When something needs to stand apart, use weight, a rule, or a neutral — not a new hue. Green and red are reserved for direction and mean nothing else.
- `--chrome-hi` is a *state* derived from `--chrome-2` toward `--ink`, not a fourth surface. It exists because collapsing the neutral ramp to three steps left hover states resolving to the same value as the surface beneath them. Use it for hover/active fills.
- **Metrics are tabular rows, not tiles** — `.mgrid` is `display: block` and `.metric` is a flex row with the value right-aligned on a shared axis, so values compare down a column. `metric(label, value, cls)` renders it. Below ~380px of pane, `syncMetricDensity()` adds `.stack-metrics` to stack label-over-value.
- **Cards are hairline-separated sections**, not panels: no background, no shadow, no radius, no icons. `card(id, title, bodyHtml, opts)` takes **four** arguments — there is no icon parameter.
- **Motion encodes state; it never announces arrival.** Progress fills, streaming carets, score-bar growth, count-ups, scroll reveals and theme crossfades stay. Entrance cascades, pop-ins and idle ambience were deliberately removed. The hero is exempt — it is not an instrument surface.

## Conventions & gotchas

- **Vanilla everything.** Adding a dependency is a real decision — Node currently ships zero. Don't reach for a framework or library without cause.
- **The SSE event names are a contract** between server.js (`send(event, ...)`) and app.js (`addEventListener(event, ...)`). This holds for both the analyzer (`progress`/`result`/`ai_*`) and screener (`screen_*`) event families. Renaming one side silently breaks the UI.
- **A clean stream is not a finished answer — always read `finish_reason`.** A response that stops because it hit `max_tokens` does not fail: the SSE stream closes normally, with no error chunk and no dropped socket, carrying `finish_reason: "length"` (or a provider's own wording in `native_finish_reason`, hence the loose `TRUNCATED_REASON` match). Reading `delta.reasoning`/`delta.content` alone, a truncated write-up and a complete one are byte-for-byte identical — which is exactly how the analyzer used to render a fragment as "Analysis complete" at 100% with no Retry, and how `/chat` reported a thinking loop as "the model returned an empty response — please try again", sending the user back into the identical request. All four AI call sites now go through `newAiStreamState` / `readAiStreamLine` / `aiStreamTruncated` so the three streaming loops cannot drift, and truncation surfaces as `ai_error` with `truncated: true` (never `ai_done`) per the existing rule that an interrupted stream must never look finished. **A truncation is deliberately not retried** — the request would be identical, so it would hit the same ceiling and spend the budget twice; raise `SQUALL_ANALYSIS_MAX` or lower `SQUALL_REASON_EFFORT` instead. On `/backtest-stream` it also forces `revealOutcomes(null)`, because the forced long/short position is written at the *end* of the write-up, so a cut-off answer is precisely the one whose decision is missing.
- **`usage` only arrives if you ask for it** (`usage: { include: true }`), and it is the sole evidence channel for a reasoning loop. `describeAiStream` logs one line per call — `provider=… finish=… reasoning=N answer=N chars=N` — and **reasoning tokens pinned near the budget with an answer near zero is the signature to look for**: that is a model that spent the whole request thinking in circles. Without that line the failure is invisible in production, since nothing throws.
- **A limit on an SSE route is reported in-band at HTTP 200, never as a 429.** `EventSource` cannot read a non-200 body — per spec any other status fails the connection with `e.data === undefined`, which app.js renders as "Connection lost. Is the server running?", exactly the wrong message for a rate limit. The discriminator is a **`limited:true` field inside the existing `error`/`screen_error` payloads**, deliberately not a new event name. The POST routes *can* set a status, so they return a real 429/503 with a JSON body — and app.js must read that body rather than throwing on the bare status.
- **A silent stream is the one failure the browser cannot report, so both ends have a fail-safe.** An `EventSource` facing a request that is never answered stays in CONNECTING and **never fires `error`** — so "the server died" and "the analysis is still running" are byte-identical to the page. That is how `/ilgar` came to sit on "Starting the historical analysis" at 1% indefinitely with the Run button latched disabled: that label is written *client-side before the stream is opened*, and nothing downstream was obliged to replace it. Three things now close it, and they are independent. (1) **The request handler is wrapped.** It is `async` and was passed straight to `http.createServer`, which does not await it, so a throw anywhere in a route both abandoned that socket with no status and surfaced as an unhandled rejection — which in Node 15+ kills the process, meaning the *next* visitor hangs against a restarting container. `failRequest` now emits that route's own terminal event (`SSE_FAIL_EVENTS` maps prefix → `backtest_error`/`screen_error`/`error`; the wrong name is as silent as none) and ends the response. (2) **`sseWriter` is why `send` cannot kill the process.** Those closures are called from a child's stderr `data` handler and from spawn callbacks — *not* on the handler's call stack — so a throw out of `res.write` on a dropped socket is an uncaught exception no `try/catch` around the handler can see. Writing to a gone peer must be a no-op. (3) **`/ilgar` has a two-window watchdog**: `BT_FIRST_EVENT_MS` (20s) because the server's first event precedes the queue, the engine and the AI and so is unconditional and immediate, and `BT_SILENCE_MS` (90s) reset by *every* event through the `on()` wrapper — generous because a long model pause and the late decision-extraction call are both normal. Registering a listener with a bare `source.addEventListener` bypasses that re-arming; `scripts/check_sse_contract.py` matches `on(` for this reason.
- **Release the concurrency slot exactly once, via the guarded closure `acquirePy` hands back.** `/analyze-stream` has three exit paths that can all fire for one request (`py` close, `py` error, `req` close). A double decrement drives the counter negative and silently uncaps concurrency for the life of the process — nothing will tell you.
- **`req` vs `res` for detecting a disconnect is not interchangeable.** On a POST, the request stream auto-destroys and emits `close` the instant its body is consumed (Node 16+), so anything waiting on `req.on("close")` there fires immediately: use `res`. On the SSE GETs, `req` is correct. `/chat` already documented this trap; `acquirePy` takes the abort source as an explicit argument for the same reason.
- **A tie is not a verdict, and a clamped score is not a probability.** Two defects in the deterministic signal layer drove four of the five worst calls in the `/ilgar` audit, and both were invisible because nothing raised. (1) `analyze_institutional` set `net_bias` with `dist >= acc` against a falling OBV, and the tie that actually occurs is `0 == 0` — no high-volume day in either direction over 25 sessions, i.e. **no evidence at all** — which returned DISTRIBUTION. `classify_market_regime` then rewards that with up to 7 points, enough to win outright: NVDA 2023-01-17 scored DISTRIBUTION 7 where *all seven points traced to the tie*, and the analysis shorted it two weeks before a +166% run while quoting the regime back as "the more statistically weighted signal". `up_vol_ratio` was computed in the same function and never consulted; NVDA's was 0.68. It now breaks the tie, using the same 0.60/0.42 thresholds `classify_market_regime` already applies, so the two cannot disagree. (2) `confidence = int(max(45, min(92, 48 + winner*5 + gap*4)))` **saturates at 92** — 11 of 18 replays returned exactly that against an observed range of only 68-92 — and 15 of 18 write-ups quoted it back as a forecast probability. It survives for the dashboard meter, which renders it as a bar beside a "does not predict the next move" note, but **no prompt may carry it**: both builders go through `regime_for_prompt`, which ships `separation` (wide/moderate/narrow) and a self-describing `basis` string instead. `classify_market_regime` also emits `conflicts`, because a winning bucket is a sum and a label can win while its inputs point opposite ways — ACCUMULATION sitting on its own "Structure: downtrend" evidence line produced the two worst longs, and the model resolved that pairing bullishly both times because nothing marked it as a conflict.
- **An empty `support`/`resistance` list is a detector outcome, not a finding.** A stock making new lows has no prior trough beneath it to cluster, so `[]` is the *expected* result at a 52-week extreme. Shipped bare it was read as evidence: 4 of 18 replays had no supports and 3 turned it into a bear point, AMD 2025-04-07 writing "has no identified support" into its bear case eight sessions before the low. `detect_chart_patterns` now attaches `levels_note` saying which it is; only that function knows.
- **stdout is sacred in both Python engines** — any stray `print()` to stdout corrupts the JSON the server parses. Diagnostic output must go to stderr (scraperFinal.py uses `SEC_DIAGNOSTICS` + `STAGE|`; screener.py uses `PROGRESS|`/`STAGE|`/`WARN|`). Corollary: **serialize the whole payload to a string before writing a byte of it.** `json.dump(obj, sys.stdout)` streams as it encodes, so a value it can't encode leaves half an object on stdout and the top-level handler then appends its own JSON — producing a stream nothing can parse. Both engines pass `allow_nan=False`, because the permissive default emits bare `NaN`/`Infinity`, which is *not valid JSON*: Python raises nothing and the only symptom is a parse failure in Node with no clue which field caused it.
- **Guard NaN before `int()`.** `int(x or 0)` looks like a guard and isn't — `bool(float("nan"))` is `True` in Python, so NaN sails through the `or` and `int(NaN)` raises `ValueError`. Providers return NaN volume routinely. Use `safe_int` (scraperFinal.py) or `finite()` (screener.py).
- **Anything that adds an upstream request needs a rate story, not just a cost story.** All sec.gov calls must route through `_sec_throttle` in scraperFinal.py — including raw `requests.get` calls, three of which bypassed `_sec_get` for a long time and were the densest part of a run. Any loop that fetches one document per filing needs a cap (`SEC_MAX_FILING_FETCHES`), because filing counts are unbounded per issuer.
- **Every engine run is bounded by a wall clock** (`SQUALL_SCRAPER_TIMEOUT_MS` / `SQUALL_SCREENER_TIMEOUT_MS`) and killed past it. This is not optional politeness: concurrent subprocesses are capped, so one wedged engine holds a slot that other users queue behind, and `MAX_PY` hangs take the site down until the container restarts. Any new subprocess needs the same treatment.
- **The screener concept vocabulary is duplicated in three places** — `SCREENER_CATALOG` (server.js, the authoritative id→label+definition map, also fed to the interpreter model), the `scores` computed per concept in `screener.py`, and `SCREEN_CONCEPT_LABELS` in app.js. Adding a concept means touching all three: a concept the server accepts but screener.py doesn't score silently returns a neutral 50. `CACHE_VERSION` in screener.py must be bumped whenever the scored fields change, or stale caches serve incomplete rows.
- **Progress protocols differ:** the analyzer emits 7 scraper stages (`STAGE_TOTAL` in server.js) and the browser maps those into the first portion of its full data/render/AI progress. The screener emits explicit 0–100 `PROGRESS|` values tied to completed data batches, scoring, and explanations.
- **Profiles and saved tabs/screens are localStorage-only.** MySquall never leaves the browser except as a sanitized `profile=` param per request; there is no server-side persistence.
- **`app.js` reads CSS tokens at runtime** — inline `style="…var(--ink-dim)…"` strings and, in the canvas code, `cssVar("--up")` / `cssVar("--chrome-1")`. Renaming or deleting a token means grepping **both** files, not just the stylesheet. A canvas that silently loses its colors is the failure mode; there is no error. `cssVar` is **memoized and only invalidated on `squall:theme`** — it was a fresh `getComputedStyle` per call inside the per-candle draw loop. Nothing may mutate a token outside `commitTheme` without dispatching that event.
- **A front-end change is not verified until it has run on both pages.** `app.js` is shared, so a change that only makes sense on the analyzer can silently kill `/screener` at load — and the symptom is not an error you'll notice, it's every listener below the throw quietly never wiring up. Grepping is not enough: the fatal shape (`document.getElementById(x).addEventListener(...)` at top level) is indistinguishable from the safe one until you know whether `x` is in that page's markup. `tests/js/pagecheck.js` executes each page's scripts against that page's real id set and self-validates on every run. It covers `index.html`, `screener.html`, `ilgar.html` and `404.html`, and **inline `<script>` blocks count as scripts** — a page whose whole behavior is inline (404.html) would otherwise be listed as passing while executing nothing, and an uncovered inline block fails exactly like an uncovered file: first throw, every listener below it dead, page still renders. **Validate the checker before trusting it**: run it against the pre-change code and confirm it fails. The first version of both checks used here reported a clean pass on code that was definitely broken.
- **`pagecheck` seeds a saved analysis into localStorage, and that is not incidental.** With an empty store `drawChart` returns at its `!sess` guard and every line past it is dead code, so a `const` referenced inside it but declared further down the file — a temporal dead zone that throws in any browser holding a saved tab — passes clean. The seed makes the returning-visitor path the tested one and carries a **legacy numeric `range`**, so the migration is exercised every run. `app.js` calls `applyTheme()` at load and `applyTheme` repaints the chart, which is why anything `drawChart` touches must be declared above the theme init near the top of the file.
- **`tests/stubs/scraper_stub.js`** stands in for `scraperFinal.py` (same argv/stdout/stderr contract) so the whole server path and front end run on a box with no Python: `PORT=3271 PYTHON_BIN=node SQUALL_SCRAPER_PATH=./tests/stubs/scraper_stub.js node server.js`. `STUB_NO_INTRADAY=1` produces the fund/thin-name payload where the intraday tiers must disappear.
- **The automation browser tab is backgrounded, so `requestAnimationFrame` never fires there.** `renderAll` ends with `requestAnimationFrame(drawChart)`, so a canvas measured straight after a render in an MCP-driven tab reads as blank — call `drawChart()` directly before measuring. Same for `await new Promise(r => requestAnimationFrame(r))`, which simply hangs. Element `getComputedStyle` also lags a `dataset.theme` switch by one iteration in a loop; measure token pairs through a probe element instead of reading colors off live elements.
- **Verify styling by measuring the live DOM, not by reading the source.** There is no linter to catch a token that resolves to nothing. Cycle `document.documentElement.dataset.theme` over all six ids and read `getComputedStyle` — a `var()` pointing at a deleted token resolves to empty, the declaration is dropped, and the element silently inherits. Two checks worth repeating after any token change: every `var()` referenced in the stylesheet resolves in every theme, and no rendered element computes a font-size below 10px.
- **Check contrast against the surface an element actually sits on.** Cards are transparent, so card text resolves against `--chrome-0` (the page), while screener results sit on `--chrome-1`. Daylight silently fell under WCAG AA once when text moved from one to the other. When you change a surface or an ink value, re-measure both pairings across all six themes.
- **A "state" that resolves to the same color as its backdrop is invisible, and nothing will tell you.** This bit six separate hover/loading states at once when two neutral tokens were merged. After any surface change, confirm hover/active/focus fills still differ from what they sit on — Daylight is the worst case, where `--chrome-0` and `--chrome-2` are within ~1.2:1 and a background tint alone cannot carry an affordance.
